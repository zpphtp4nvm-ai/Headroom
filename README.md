# Headroom

Headroom is a Windows 11 debloat and gaming tune-up tool, written as a single PowerShell script with a window you click through. It has about 210 settings in 20 groups, and each one is its own switch. Every setting says what it changes and lists the registry values, services, scheduled tasks, features or apps it touches. It reads the current state from your PC, so you can see what’s already on or off before you change anything. Each card also says what Windows itself does by default ("Windows default: On" or "Windows default: Off").

There are two presets. The Question Preset asks short questions about how you use the PC (gaming, Riot or FACEIT games, a VPN, virtual machines, printing and so on) and changes only what fits your answers; a question you answer Not sure to, or skip, changes nothing. Custom Preset saves your own choices so you can reapply them after a clean install. Each preset lists exactly what it will change before it does anything. A Preview only switch shows what would happen without changing anything, and a few settings (anything that could break FACEIT or Riot Vanguard, printing, or virtual machines) inform you they will break these services.

The Home page shows your Windows version, CPU, graphics card, memory, motherboard, displays and drives as cards, two to a row, in the same style as the setting cards: a small label at the top, the name, then tags (the maker in its colour, then facts such as the build, the core count or the driver version). The CPU and graphics card show their load as a big percentage with a bar and their power, temperature and clock on tiles, the memory card shows how much is in use and how much is free, and a green dot marks a reading that is set the way that is best for gaming. Copy system info, a button at the top of Home next to Start HWiNFO, puts the text of every card on the clipboard so you can paste it into a forum post or a support chat. Windows doesn’t report CPU temperature, CPU power or memory timings, so those come from HWiNFO or LibreHardwareMonitor if one is running. On an NVIDIA card the graphics card also shows whether Resizable BAR is on and the PCIe link generation and width, read from nvidia-smi. The Storage card shows the PCIe link of each NVMe drive (generation and lanes, for example Gen 5 x4), read from the properties Windows keeps on the drive's PCI device; it has a green dot when the drive runs at the best link it supports, says so when it runs at a lower generation (the slot may allow no more), and warns when it has fewer lanes than it supports.

A Timer and clock card shows the timer resolution Windows is using right now (how often its clock ticks; a program can ask for a finer tick), whether the HPET is present and enabled, which clock sits behind QueryPerformanceCounter (TSC, HPET or ACPI timer, worked out from how long one read takes), and any timer options set in the boot entry (useplatformclock, useplatformtick, disabledynamictick, tscsyncpolicy). A Platform security card shows whether Secure Boot is on (a green dot; some anti-cheats need it, and a PC that starts in legacy BIOS mode cannot use it), whether virtualization-based security (VBS) is running, whether memory integrity (HVCI) is on, and whether the IOMMU (AMD-Vi or VT-d) is on in the BIOS. Click any line or tile in these two to see what it means and what Windows has by default; click again to close it. A Mouse card shows whether Enhance pointer precision is off, whether the pointer speed is at the middle notch (10 of 20, 1:1) and whether USB selective suspend is off in the power plan in use; each one that is set for gaming has a green dot, and each line explains itself on a click. The Windows card also shows whether fast startup is on (a green dot when it is off, so Shut down starts Windows and its drivers fresh; it also says when hibernation, which fast startup needs, is off, or when a policy requires it). Everything on these pages is read only: Secure Boot and fast startup are read from the registry, the timer is only asked for, the boot entry is only listed with `bcdedit /enum`, the device list and the drives' PCIe link, Windows' Device Guard report and the mouse settings are only read, the firmware's ACPI tables are only listed, and the power plan is only shown with `powercfg /q`. Copy system info only writes to the clipboard. The one exception is the Start HWiNFO button, which changes HWiNFO's own settings file after asking.

## Requirements

- Windows 11
- Windows PowerShell 5.1 (already included in Windows 11), the 64-bit one
- An administrator account

Headroom does not install on the device.

## Run it

### From an administrator PowerShell

```powershell
irm https://raw.githubusercontent.com/zpphtp4nvm-ai/Headroom/main/Headroom.ps1 | iex
```

Closing Headroom ends that PowerShell window, so use the first command if you want to keep the window.

### Command-line options through irm

Run this from an administrator PowerShell. It starts a separate PowerShell, so your own window stays open.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create((irm https://raw.githubusercontent.com/zpphtp4nvm-ai/Headroom/main/Headroom.ps1))) -NoGui -List"
```

Change `-NoGui -List` to any of the options below.

### Download and run

1. Download `Headroom.ps1` and `Start-Headroom.bat` into the same folder.
2. Double-click `Start-Headroom.bat`. It asks Windows for administrator permission and opens the window.

If Windows blocks the files because they came from the internet, right-click each one, choose Properties, tick Unblock, and press OK.

## Read it before you run it

Headroom changes Windows settings, and it runs as administrator. Read the script first, or pin the command to a fixed commit instead of `main` so it cannot change underneath you:

```powershell
irm https://raw.githubusercontent.com/zpphtp4nvm-ai/Headroom/<commit-hash>/Headroom.ps1 | iex
```

The Preview only switch (or `-DryRun` in the console) lists what would happen and changes nothing.

## Presets

Select Optimization Preset offers two presets. Each one lists what it will change before anything is applied.

| Preset | What it is |
| --- | --- |
| Question Preset | A list of questions about how you use the PC. Your answers decide which settings change, and a setting you are unsure about is left as it is. |
| Custom Preset | Your own saved configuration, which can be applied again after a clean install of Windows. |

How the Question Preset works:

- Each question is Yes, No, Not sure or Use default, with a short explanation and the settings the answer would change. You can go back to an earlier question and start again.
- Use default leaves that question's settings as Windows has them. Any of them that are changed on your PC are put back to the Windows default when you press Confirm changes. Settings that remove an app cannot be put back, so those stay as they are.
- Not sure and a skipped question change nothing. A Yes to a question that protects a setting (for example a Yes to Riot or FACEIT games, virtual machines or printing) beats any other answer that would change it.
- The questions are grouped: your PC, work and network, accounts and cloud, privacy, AI and Edge, look and feel, and built-in apps. Questions that only matter for gaming PCs are left out if you say you do not game. Removing built-in apps is its own question at the start, and settings that cannot be undone are only applied if you say Yes to it.
- Near the start it also asks whether you want the advanced questions. Those cover settings that lower protection or can get in the way of other things (User Account Control, drive encryption, driver updates, the Microsoft Store and similar). If you say No or Not sure they are not asked and nothing in them changes.
- Before anything is applied, a review page lists every setting that will change, every setting that is kept as it is and why, and the ones marked Not recommended or lowering protection. A restore point is created first.

Settings that can stop FACEIT or Riot Vanguard, printing, or virtual machines ask first.

## Command line

```powershell
.\Headroom.ps1                                    # opens the window
.\Headroom.ps1 -NoGui -List                       # every setting, its switch, and the Windows default
.\Headroom.ps1 -NoGui -Preset -DryRun             # preview the built-in recommended set (the Question Preset is only in the window)
.\Headroom.ps1 -NoGui -Apply mouse,gamedvr        # just those two
.\Headroom.ps1 -NoGui -Apply mpo=full             # Multiplane Overlay: Fully disabled
.\Headroom.ps1 -NoGui -Undo mpo                   # and back to Enabled (the Windows default)
```

| Option | Meaning |
| --- | --- |
| `-NoGui` | Do not open the window; work in the console. Without `-List`, `-Preset`, `-Apply` or `-Undo` it shows the state of every setting. |
| `-DryRun` | Window: starts with Preview only switched on. Console: shows what would happen and changes nothing. |
| `-List` | Console: print every setting with its id, whether its switch is on or off, the Windows default, and which way `-Apply` turns the switch. |
| `-Preset` | Console: turn on the built-in recommended set, a group of gaming-oriented settings that removes no app. The Question Preset is only in the window. |
| `-Apply` | Console: apply these setting ids (see `-List`; each one says whether `-Apply` turns its switch on or off). A setting with options takes one as `id=option`. |
| `-Undo` | Console: put the Windows default back for these setting ids. |

## What the switches do

Each card has one switch, and the switch is the setting itself. A card (build 126) shows its id, its name, its tags (the page, Not recommended, Needs restart, Recommended and so on), the start of its description, its risk, and two buttons: View Description opens a window with the whole description, the Windows default, what is waiting and exactly what the setting changes; `</>` opens a window with every value of the setting as the last check read it from your PC, and what Headroom changes it to. Both windows follow the card you select while they are open, and neither changes anything. On means the setting is on, off means it is off (or back at the Windows default, depending on what the setting does). The card's text has an "On:" half and an "Off:" half that say what each position means, and the "Windows default" tag tells you which position Windows ships with.

- Game Mode: on turns Windows Game Mode on, off turns it off. The same goes for Optimizations for windowed games.
- A service: on lets the service start the way Windows has it, off disables it.
- A feature that is on in Windows by default (Xbox Game Bar, telemetry, widgets and so on): the switch starts on, and switching it off turns the feature off.
- A feature that Windows has off by default: the switch starts off, and switching it on turns the feature on.
- A startup program: on means it starts with Windows, off means it does not. It is the same switch Task Manager uses, kept where Windows reads it: for your account for a program in your own Run list or Startup folder, and for every account for one in the all-users Run list or Startup folder.
- A setting that has a switch in Windows Settings (or in Windows Security, or a box in a classic Control Panel dialog) writes exactly what that switch writes, and nothing else: no Group Policy, no extra registry values, no services. Switched on it is the same as turning the switch on in Settings, switched off the same as turning it off. Where Windows has a Group Policy for that switch, the policy goes with the card's switch (build 126, see below), so after you switch such a card off, Settings shows that switch as "managed by your organization" until you switch the card back on in Headroom. A switch Windows ships off, where no value means off (clipboard history, clipboard sync, Record what happened, title bar window shake), shows as off on a PC where it was never touched, and Apply all, Tweak all and the presets still turn it off for real: they write the value Settings writes when you switch it off, so afterwards its reading shows that value (build 125). Reset all takes the value away again, which is how Windows ships it. A few values earlier builds wrote are still cleaned up when you apply the setting or switch it back on, but only while they still have the value Headroom wrote, and they are never put back: the Defender sample-submission policy (security software flags that value, and Tamper Protection can ignore it, so Windows Security's own switch is used), the notification-centre and Spotlight policies (they turn off more than their switch: the notification centre, Spotlight pictures), LetAppsAccessSystemAIModels (Microsoft documents no such policy), an old Chrome value and the feedback period that "Never" removes. Once such a value is gone it is no longer listed in the reading. Values earlier builds wrote that only keep something off (a 0 that blocks, not a policy) are left as they are, and no clean-up ever sets anything to allow.
- Values that go with a card (build 126): the registry values that belong to a card for a Settings switch but that the switch itself does not write, and the Group Policy of that switch, are part of the card again. Builds 124 and 125 had them as a second switch in a small box under the card, called "Disable in registry", with a Sync Registry Changes switch to move both together; build 126 removed the boxes and Sync. Switching the card off writes them with the switch, switching it back on (or Reset all) takes them away again, which is how Windows ships them. A card whose switch is already off but whose values are not all written yet still reads off, and Apply all, Tweak all and the presets write what is missing. The 24 cards that have such values: Optional diagnostic data (error reporting and the other diagnostic policies, and the diagnostic data level policy), Advertising ID and tailored experiences, Feedback pop-ups, Inking, typing and speech data collection (the handwriting data policies and online speech recognition, which voice typing needs), Location services, Find my device, Device info and apps from the internet, Clipboard history, Clipboard history across your devices, Nearby sharing and Share across devices (Continue experiences on this device), Resume apps from your phone (only where Windows has that policy), Windows Update peer-to-peer sharing (Delivery Optimization), Remote Desktop, Remote Assistance, File and printer sharing (the default C$ and ADMIN$ shares), "Record what happened" (Game DVR capture and Game Bar's helpers), Memory Integrity (VBS and Credential Guard; it asks the anti-cheat question), the Widgets and Chat taskbar buttons (the Widgets feed and Chat icon policies; Windows refuses the Widgets switch from a script on newer builds, so this policy is the way to hide Widgets there), Notifications, Tips and suggestions from Windows (sponsored and auto-installed apps, and the Windows tips policy, written only on Enterprise and Education, the only editions that obey it), Search history, highlights, cloud search (the web and cloud search policies), the Copilot taskbar button, App access to generative AI, and Voice activation. The old box ids still work in the console and in a saved Custom Preset or configuration: each one means its card. The services that used to be part of such a card (Geolocation, Connected Devices, Delivery Optimization, Remote Desktop, the Server service and the network discovery services) are cards of their own on the Services page, and the two adapter bindings are cards on the Network sharing page.
- Group Policy is also used where Windows Settings has no switch at all: LLMNR, driver updates through Windows Update, automatic updates, OneDrive sync, Recall, the Settings home cards and the Store. Activity history and Settings sync stay policies, because what their Settings switches write is not documented.
- Browser settings (Edge and Chrome) are policies. Edge and Chrome show "Managed by your organization" while any of their policies is set; switching the setting off removes the policy values again. Chrome has no group of its own, so its AI setting is on the AI features page next to the Windows ones.
- Services: every setting that only changes services is on the Services page, so they are all in one place. 21 of them are untested ideas from other debloat scripts and carry an "Untested" tag; Apply all and Tweak all leave those out, so you switch them yourself. Build 124 added 13 of them: Bluetooth (four services), Windows Push Notifications, scanner and camera import (WIA), Encrypting File System, File History, Windows Event Collector, Application Identity (AppLocker), Agent Activation Runtime, GameDVR and Broadcast, Messaging, DevQuery Background Discovery, three more printing services and three more troubleshooting services. Bluetooth and Push Notifications are marked "Not recommended". Switched off, each is set to Disabled; switched on, it gets the start type Windows ships it with.
- Testing page (build 124): it is still in the menu, last, at 0/0. The settings that were on it now sit on the pages they belong to. Mouse Keys and High Contrast are with the other keyboard shortcuts on Gaming and performance (they were already in the Recommended preset). The other twelve are ordinary cards, so Apply all and Tweak all take them like any other: volume ducking, Automatic Maintenance and the WinSAT and Xbox game save tasks on Gaming and performance; the Software Quality Metrics, Office telemetry, Compatibility Assistant, Data usage and Family Safety tasks on Privacy and telemetry; the Maps update task on Cloud, sync and OneDrive; the power diagnostics task on Power plan and startup; and the classic File Explorer toolbar on File Explorer.
- OneDrive app (build 124): it is not removed while OneDrive is backing up your Desktop, Documents, Pictures, Music or Videos. Those folders are then inside the OneDrive folder, and files there that are kept online only could not be opened once OneDrive is gone. Stop the backup in OneDrive's settings first (Sync and backup > Manage back up); the card says which folders it found.
- Home and Gallery in the File Explorer side pane (build 124): switching them back on, or Reset all, also deletes the per-user registry key the hide value was in once it is empty. Left behind, the empty key could keep the entry hidden, because Windows reads that key in place of its own.
- Recall (build 124): on a Copilot+ PC the Windows AI Components Host (WSAIFabricSvc) is set to Manual, not Disabled, because a disabled host has been reported to leave the taskbar and tray icons missing since the July 2026 updates. If something else disabled it, the card reads as partly applied, and finishing it sets Manual. Switched back on, the host goes back to Automatic, how Windows 11 25H2 and later ship it.
- Settings with options and one-time actions: a setting with options that is sitting on its Windows default (Multiplane Overlay, automatic updates for Store apps) and the run-once actions (Disk Cleanup, Temporary files) are listed under All settings but not counted as "Not applied", because there is nothing to apply until you pick an option or line the action up. They count again as soon as you do.

Switching a single card works like the switch in Windows Settings, both ways (dark mode is the one exception: it keeps the taskbar without an accent colour). Turning a card back on writes what Settings writes when you turn that switch on: switching diagnostic data back on turns "Send optional diagnostic data" on, clipboard history back on turns clipboard history on, Remote Desktop back on allows Remote Desktop connections, and "Record what happened" comes back on with Game Bar. Cards for features you switch on work the same the other way: HAGS switched off writes the off value (1), and the windowed-games, variable refresh rate and End task switches write 0. Title bar window shake is the Settings switch itself (build 124; it used to be "Block title bar window shake", the other way round): on writes 0, off writes 1, and a PC where it was never switched on shows it off, as Settings does. Memory Integrity is the one Settings switch Headroom does not force on: Windows Security checks your drivers before it turns it on, and doing it from the registry would skip that check, so switching the card back puts back what the PC had.

Reset all puts everything back to the Windows default, which means Game Mode and Optimizations for windowed games go back to on. It never turns on something Windows ships switched off: Remote Desktop stays off, clipboard history and the cloud clipboard stay off, "Record what happened" and title bar window shake stay off, Nearby sharing goes back to off (or to what the PC had before), and HAGS goes back to what the driver decides. When the check of the PC finds a setting that is only partly in place, Headroom offers to finish it. It makes the same offer for a setting that Headroom applied earlier and that now reads off, for example after a newer build changes that setting or a driver install puts a value back. Settings with options and run-once actions are left out, and so is Game Mode, because switching it off in Windows is your choice. Click a setting in that window to open it and see exactly what changed: each value, what kind of thing it is (a registry value, a service, a scheduled task and so on), where it is, what it is now and what Headroom sets. Show all changes opens them all. Each setting has a tick box, all ticked at first: untick the ones you want to leave as they are (or use Select none and tick a few), and Apply puts back only the ticked ones; Leave as is changes nothing.

When a setting is put back to the Windows default, that covers everything it changed: registry values (deleted where Windows sets none), service start types, scheduled tasks, firewall rules (as Windows ships them), adapter bindings and driver options (the driver's own default), the power settings of USB devices (what each device had before Headroom first changed it, since a driver can ship its own values) and the boot setting for the hypervisor. For the power plan switches the Windows default is Balanced and High Performance installed and the other four not installed. It does not put back what your PC had before Headroom changed it, so a value that another tool had set earlier also ends up at the Windows default. The exceptions are Memory Integrity and VBS and Credential Guard (four DeviceGuard and LSA values) and the hypervisor boot setting, whose Windows default differs from PC to PC: Windows turns Memory Integrity on by itself on a clean install on capable hardware, and Hyper-V, WSL2 and Windows Sandbox set the hypervisor to Auto. For those, switching the setting back on puts back what the PC had before Headroom changed it, and a value that was not there is removed again. The same goes for a few values that Windows or the Settings app writes differently from PC to PC: the Settings app's own copy of tailored experiences, Copilot's eligibility value, the location prompt and location override switches, the Resume switches, and the three values the "Send optional diagnostic data" switch writes. Build 121 also set the value Windows keeps for the DisableCrossDeviceResume policy; build 122 puts it back to 0 (Resume allowed), never deletes it, and leaves only the two Resume switches.

A few settings are handled differently:

- Settings that add or remove Windows components (optional features and capabilities, such as SMB1) use the record of what was installed when Headroom first changed them, because Windows has no single default for those. The same record is used for firewall rules if Windows' own list of default rules cannot be read.
- Some defaults depend on the PC (for example hardware GPU scheduling, Memory Integrity and BitLocker). Those cards say "Depends on the PC" instead of On or Off. Where Windows keeps no value until a switch is first changed, the card goes by what Windows actually does (build 127): hardware-accelerated GPU scheduling asks the graphics driver whether it is on, the same place Settings gets it from, so a card whose driver has it on by default shows on; Memory Integrity asks Windows' own security report, so a PC where it was never switched on shows it off, as Windows Security does; Storage Sense with no value shows off, because Windows keeps it off until disk space runs low or you turn it on. Reset all leaves such a card alone, because that already is the Windows default. The Widgets and Chat card no longer reads "partly applied" because of the Chat value, which Windows 11 23H2 and later do not use.
- Tips and suggestions from Windows (build 128) no longer sets ContentDeliveryAllowed to 0, because that also stops Windows Spotlight pictures on the lock screen; the other content-delivery values still stop the promoted content and silently installed apps. Where an earlier build left it at 0, applying or undoing the card sets it back to 1, the Windows default.
- Settings that remove apps cannot be undone from Headroom.
- The five keyboard shortcut settings (Sticky Keys, Filter Keys, Toggle Keys, Mouse Keys and High Contrast) do what turning the shortcut off in Settings does: only the shortcut's bit is taken out of the value your account has, and the feature and its other options stay as they are. From Windows' defaults that gives 506, 122, 58, 58 and 122. Switching one back on puts only that bit back. Headroom only writes that registry value and does nothing else, so the change works from your next sign-in.
- The App permissions settings on the Privacy page (personal info, files, radios and other devices, passkeys) and on the AI features page (text and image generation) set the switches under Settings > Privacy and security > App permissions to Deny for every app, and switching them back on sets them to Allow, the Windows default. Camera and microphone are never touched. Normal desktop programs don't use these permissions; Store apps such as Mail, Calendar, Photos and Phone Link do.
- Mouse acceleration changes only the three values behind "Enhance pointer precision" (MouseSpeed and the two thresholds), in the registry and in the running session, the way the Mouse settings box does. Your pointer speed is never touched, not even in the running session.
- Keyboard repeat delay (build 126, on Gaming and performance) is the Repeat delay slider of the Keyboard control panel: off sets it to Short (KeyboardDelay 0, about a quarter of a second before a held key repeats), on puts back the Windows default (1, about half a second). The repeat rate is not touched, and the first key press reaches a game just as fast either way. Menu open delay (build 126, on Look and feel) is how long a classic menu waits before opening a submenu under the pointer: off sets MenuShowDelay to 0, on puts back the Windows 400 ms. Both are applied to the running session at once, the way the control panel does it, and neither is in a preset.
- Telemetry scheduled tasks includes StartupAppTask, the task that measures how much each startup app slows down sign-in. While it is off, Task Manager's Startup apps page can show "Not measured" in its Startup impact column.
- The background mouse rate cap setting removes the limit Windows 11 puts on how often programs in the background hear about mouse movement. Microsoft added that limit to stop stutter with high polling rate mice, so the card is marked Not recommended: only switch it off if a game feels like a 125 Hz mouse.
- Automatic offline map updates (build 126, on Cloud, sync and OneDrive; it was the Maps update task card): off turns off "Update automatically when plugged in and on Wi-Fi" in Settings > Apps > Offline maps (AutoUpdateEnabled = 0, what that switch writes) and disables the Maps update task. Switching it back on writes 1 and enables the task again. On a PC without the task only the switch is set. The Maps Group Policy is not set. The Windows Maps app no longer works, and newer Windows 11 builds are removing Offline maps from Settings.
- The Power page has a switch for each of six power plans: Balanced, High Performance, Ultimate Performance, Ultimate Plan Modified, Khorvie's PowerPlan and the Low Latency Power Plan (amit's low latency powerplan, the idle enabled version; Headroom installs it under the name Low Latency Power Plan). A switch that is on means the plan is installed. Switching one on only installs it and leaves the active plan as it is; an installed plan that isn't the active one has a Make active button on its card, and the active plan's card says Active plan. Every installed plan also has a Reinstall button, which asks first and then makes the plan again the way Headroom installs it, so anything changed inside it is gone: for Balanced and High Performance Windows' own Restore plan defaults is used where Windows can, otherwise the plan is deleted and installed again, but only after Headroom has made sure it can be made again (Windows keeps defaults for it, Windows makes Ultimate Performance, the plan file is intact). The active plan stays the active plan, and a restore point is made first. Switching a plan off deletes that plan and no other. If it is the active plan, Balanced is made active first (or High Performance, Ultimate Performance or any other plan that is left when Balanced isn't there), and the last plan on the PC is never deleted. Balanced and High Performance come back under their usual IDs with Windows' own settings (`powercfg /duplicatescheme`). Once one has been deleted Windows has nothing left to copy. Headroom then first asks Windows to put back its own (`PowerRestoreIndividualDefaultPowerScheme`, what Restore plan defaults uses); where Windows cannot, Headroom copies the active plan under the plan's usual ID, names it, sets the values Windows keeps as that plan's defaults (under `PowerSettings\...\DefaultPowerSchemeValues` in the registry) and asks Windows to reset it. Either way every value is then checked against those defaults, one that differs is set to its default, and the log says how many were checked. On a PC with Modern Standby, Windows may refuse to create High Performance, and then nothing is changed. Ultimate Performance is installed exactly as Windows makes it, from Windows' own hidden copy, and nothing is changed in it (builds before 113 also switched off USB and Wi-Fi power saving in it; switch it off and on again to get Windows' own). Ultimate Plan Modified is that earlier version as a plan of its own: a copy of Windows' Ultimate Performance under its own ID with USB selective suspend off, USB 3 link power management off and Wi-Fi power saving at Maximum performance, plugged in and on battery, so Windows' Ultimate Performance can stay installed next to it as Windows ships it. The Khorvie's and Low Latency plan files are built into Headroom and checked against their SHA-256 before `powercfg /import` gets them; the file is written to Windows' own Temp folder under a plain name first. If Windows refuses to import a plan file as a whole (one value it does not accept on that PC is enough), Headroom makes the plan from a copy of High Performance under the plan's own ID and sets the file's values one by one; a value Windows does not accept keeps the High Performance setting, and the log names it. The presets and the Question Preset never touch a power plan. The Compare Power Plans button at the top of the Power page shows the six plans side by side (processor, including the clock-change and idle thresholds; USB, PCI Express, NVMe and drive; display, sleep and wake; plugged in). A plan that is installed is read from your PC with `powercfg /qh`, which only reads; a plan that is not installed shows what it would bring (for Balanced and High Performance, the defaults Windows keeps for them on your PC). Under Balanced and High Performance it says whether they are the same as Windows' defaults or how many settings differ.
- Windows turning off network adapters goes through Windows' own adapter power settings (the "Allow the computer to turn off this device to save power" box in Device Manager), and each adapter restarts for a moment so Windows reports the change straight away (over Remote Desktop it counts from the next restart instead). An adapter that Windows doesn't report the box for uses the older registry value.
- When Windows refuses to remove an app, Headroom tries again for each account the app is installed for, closes the app first if it is running, and otherwise says Failed on the card with Windows' own message. An app that is in use may only go at the next restart; it then counts as removed, and the log says so.
- The Windows AI core package (MicrosoftWindows.Client.CoreAI) is part of Windows, so before removing it Headroom marks it deprovisioned (so Windows does not install it again), takes off Windows' own "not removable" mark where Windows has that command (`Set-NonRemovableAppsPolicy`), and marks it end of life for SYSTEM and every account. The end-of-life marks are taken out again afterwards, because left in place they can stop Windows Update from installing updates. Afterwards Headroom checks the package the same way the check of the PC does; if Windows still lists it for an account, it is removed for that account too, and if it is still there the card says Failed and names the account. Windows keeps a copy for its own system account (S-1-5-18) and puts that copy back when it is removed; no one who signs in has it, so it does not count, and the log and the card say it is there. The same goes for any app: one that only Windows' system account still has counts as removed.
- Turning off the Windows hypervisor writes `hypervisorlaunchtype off` to the boot entry and reads it back; if bcdedit does not take it, the setting says Failed with what bcdedit said. The log says what the boot entry had, whether the hypervisor is running, and what on the PC uses the hypervisor (Hyper-V, Virtual Machine Platform, Windows Hypervisor Platform, Windows Sandbox, memory integrity, Credential Guard). Turning one of those on, or its installer or an update to it, can set the boot entry back to Auto, which is why the check can offer it again.
- Some Windows-owned values are only tried: if Windows protects or rewrites one (the driver exclusion copy in Windows Update's policy state, the Delivery Optimization switch of the service account), a refusal is noted and the setting still counts as applied. The setting for the "ms-gamebar" pop-up writes two link entries; if another program already handles one of those links, Headroom leaves that one alone.

## Where things are kept

## Hardware readings

Windows does not report CPU temperature, CPU power or memory timings, so Home shows those from HWiNFO or LibreHardwareMonitor when one of them is running. The Start HWiNFO button turns on HWiNFO's sensor sharing after asking, and keeps a copy of its settings file.
